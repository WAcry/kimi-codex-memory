# DESIGN 03：生成、保留与发布

## 引用同步与生成是不同的门槛

扫描覆盖保留窗口内的来源，并对 hook 指明的会话补读。活跃、未闲置或已归档
的会话仍可能包含最近引用，所以不能把 six-hour idle 筛选用到引用同步上。

只有闲置满足配置、处于提取年龄窗口、非当前／活动／归档来源，才成为提取
候选。按最近来源优先选取少量任务。已处理内容版本通过元数据与内容指纹避免
重复调用；空结果也记录成功，必要时删除该来源的旧输出。

## Phase 1

使用基于原版、经最小修改的 v2 system/input 模板，运行时只填充 session
ID、cwd、分支提示及证据等数据占位符。
不是让模型自由浏览 JSONL。程序先构建具有角色、任务、时间与来源信息的视图：
真实用户输入与问答最高优先，最终结论其次，其他 agent／过程信息再后，工具
噪声优先截断。随后恢复时间顺序并显式标记遗漏。

问答 interaction 与工具调用关联；已回答的人类内容作为 Human 证据，不把
工具的 assistant 包装当成用户偏好。注入内容与 thinking 不作为新的人类证据。

模型没有工具。严格验证只含 rollout_summary 和 rollout_slug 两个字符串，
检查空输出与字节限制，并在发送前及存储前尽力脱敏。模型改变不保证内容质量
或措辞与 Codex 相同；确定性机制测试与模型质量评估是两件事。

## SQLite 与租约

每个提取任务及全局合并任务都使用随机 owner token、租约期限、心跳和有界
重试等待。任何结果写入都核对有效 owner，旧 worker 不能覆盖新 owner。
模型请求与历史读取不在数据库事务内执行。

summary 更新保留已有 usage_count/last_usage；使用时间取回答的完成时间，
乱序补读不能把时间往回改。收据与计数在一个事务内完成。未生成的来源不会
因为被引用而凭空创建摘要。

## 保留规则

参与合并的来源先满足：

```sql
COALESCE(last_usage, source_updated_at) >= retention_cutoff
```

之后按 usage_count、上述时间、source_updated_at、source_id 降序排名，取
配置上限，再按 source ID 稳定排序输出。不要改成生成时间或 MAX 两个时间。

上次成功合并选中的来源不直接物理删除。退出新选集先表现为摘要文件 diff 中
的删除，由合并去掉仅由它支持的派生内容；成功后更新 selected 标记，后续再
物理清理未选中的过期行。高引用次数不能绕过时间筛选。

排除项目／来源会从新选集中移出，但旧发布版本在成功替换前仍可读。数据库
物理清理与派生遗忘不是同一瞬间发生。原始 Kimi 会话不被本项目删除。

## Phase 2

上次发布版本是 Git 基线，将新选中的摘要与 extensions 物化后计算 diff。
相同输入且摘要格式有效时不调用模型。合并只操作临时工作区，工具只有
read_file、list_files、write_summary；先读 diff，唯一可写产物是 memory_summary.md。

不开放 shell、网络、任意用户文件或原始会话。工具错误以有限、安全的响应
返回模型；超出请求次数、上下文预算或读文件上限，失败并保留旧产物。

最终产物必须以 v1 格式标记开头，包含四个规定标题且顺序正确；来源文件指针
必须存在于本次供应的集合。该检查不是事实正确性的证明。

## 发布与恢复

1. 完成临时工作区，校验和脱敏，更新内部单提交基线，写 manifest。
2. 将工作区移入独立 generation 目录。
3. 在 SQLite 写入待发布意图，包含准确的来源内容版本。
4. 在短事务中再次核对 owner，只执行原子 current.json 文件替换。
5. 更新精确来源快照的 selected 标记、成功状态，并清除发布意图。

如果在第 4 步后中断，下次 worker 以 current.json 指针与 manifest 核对后补齐
数据库；如果指针未切换，放弃未发布意图。不能仅按 source ID 把并发生成的
新版本错误标为已经合并。

这比上游部分原地文件写入采用更强的发布隔离，但仍不是跨 SQLite 与文件系统
的单一原子事务。恢复协议弥补该间隙。每个文件读取会看到完整的一个版本；
已经注入旧摘要的长会话不具有永久不失效的来源文件引用保证。

## 新输入与失败

读取完成后或模型合并期间如果又有新 hook 通知，发布／危险清理等待下一次
引用同步。仍存在事件在最终检查之后到达的极短机会式边界，不声称实现宿主
所有实时事件的强一致事务。

notes 不到期；只有规定的 extensions/<extension>/resources/ 文件依据文件名
时间执行到期移除。成功发布后才删除未被并发修改的过期 resource。

daily/run model-call budget 在发请求前预留；网络失败仍消耗一次预算，不是
货币成本计量。失败的队列通知不被确认删除；静默退避后在下一次唤醒重试。
手工 worker 命令可以直接重试。唤醒合并避免每个 hook 都启动一个竞争进程。
