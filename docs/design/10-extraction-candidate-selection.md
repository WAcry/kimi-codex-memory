# DESIGN 10：提取候选选择

## 最小实现边界

只改变 extraction_output.py 的本地候选选择：声明的工具、Prompt、
请求参数和原生 SDK/parser 都保持不变。worker 依旧在单个成功模型
响应后存储结果，没有新增工具执行器或模型循环。

_decode_candidate 是统一验证入口：严格 JSON、禁止重复 key 和
NaN/Infinity、恰好两个字符串、UTF-8、trim 后 slug 最大 256 字节，
空摘要的 slug 也必须为空。先验证再排序，避免后续写入检查发现所选
候选不可用却已经错过另一份合法结果。

工具先按 tool_calls 的原生顺序逆序检查，忽略非指定函数、坏参数和
坏调用记录。遇到第一份合法结果直接返回，完全不扫描正文。字段和
tool JSON 不做修复，只有目标结果被交给 worker。

## 正文扫描

content 来自 Kimi extractText，只包含文本 part；不递归搜索完整
响应、不拼接 reasoning。仅工具不可用时扫描其中完整对象，并按
JSON 原始片段的 UTF-8 字节数排名，相等时取后者。

扫描器一次遍历文本，跟踪对象深度、双引号和反斜杠转义。由于目标
schema 的值只能是字符串，含真正嵌套对象的外层不可能合法，故只
解码叶对象，跳过所有父容器。字符串里的花括号不是边界；不把被
转义并存放在某个字符串里的 JSON 当成新结果。候选可以出现在
解释文字、代码围栏或数组/对象的包装中，但原候选本身必须完整。

遇到无效字符串里的原始控制字符时放弃该损坏片段，继续后文；不
猜测缺失引号/括号。剩余不平衡片段不能通过验证。该策略不保证从
任意损坏外壳中找回所有可能子串，但不以修复换取伪造结果。

扫描与被解码的候选总字节量随输入线性增长；深度仅用计数器，不
对每个嵌套起点重复解码大段文本。原生响应字节上限仍适用，无新
的用户调参或无限候选存储。仅保留当前最大的合法对象。

## 失败与诊断

所有候选无效时只返回受控的 ExtractionOutputError 分类；正文、
JSON 和思考内容不写入日志。合法空结果仍受原来的完整引用同步
删除门禁约束。流完整性仍由 native requester 在进入选择器前验证，
不能从被截断响应中提前保存一份看起来已经完整的结果。

## 验证

单元测试覆盖工具纠正顺序、最后坏调用、空提交、最大合法对象、
同大小后者优先、UTF-8 长度、字段错误/重复键、引用/转义字符串、
嵌套容器、损坏前缀、深层对象线性扫描，以及从不读取思考通道。
原生三协议 SSE 测试覆盖相同选择、thinking/正文分离、截断/缺少
完成事件；冻结包对每个协议运行多工具、全坏工具、无工具三种
场景，验证单次提取、不丢健康来源、最终保存的具体结果。
