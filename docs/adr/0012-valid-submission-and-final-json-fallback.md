# ADR 0012：最后一个合法提交与最终正文 JSON 后备

状态：接受。来源：用户明确要求优先最后一个合法结果工具，全部调用
无效或没有调用时，读取模型 Output 中最大的合法 JSON；授权提交、
推送和发布补丁。此决定替代 ADR 0011 中多个调用直接失败、正文不
回退的限制，其余原生传输、工具优先和故障隔离机制保持不变。

## 选择规则

Prompt 仍要求只调用一次 submit_memory_extraction，不主动引导正文
输出，也不增加更复杂的模型对话。完整响应通过原生结束状态检查后：

1. 按返回调用顺序从后往前检查，只接受指定函数的完整合法参数。
   最后一次坏调用不遮住较早的合法调用，未知工具只忽略，不执行。
2. 只要存在合法工具结果，就不用正文，不比较工具和正文的大小。
3. 没有合法工具结果时，在原生 final text 中定位完整 JSON 对象，
   使用同一验证器筛选，选择原始 JSON 片段 UTF-8 字节数最大的一个。
   相同大小时选择后出现的对象。普通说明、代码围栏和完整外层包装
   不妨碍候选定位；不把不同片段的字段拼接起来，不补括号、引号，
   不对字符串内被转义的 JSON 再次解码。

合法不仅指语法正确：必须恰好有 rollout_summary、rollout_slug 两个
字符串，无重复/额外字段和非法 Unicode，slug/空结果关系也须符合
原来的写入约束。不先选一个大但结构错误的对象而漏掉较小合法结果。
摘要脱敏、原版大小截断及来源/租约校验仍在存储前执行。

## 不扩大的边界

解析器只接收一个成功完成的 assistant 响应，不自行重放多轮工具
会话。多个返回调用可以被容错；全部无结果时依旧走既有有界任务重试，
无需立即追问、用户开关或新增模型探测。工具参数若只是带围栏的文本
仍然不合法；正文则允许定位围栏内原本已经完整的 JSON 对象。

reasoning/thinking/_native_message 不作为正文的备选来源。流截断、
缺失结束事件、认证错误和超时不能靠正文回退变成成功。没有合法结果
时不写入、不清空旧记忆，只失败当前来源并允许其他来源继续。

这是用户明确要求的交付容错，不声称 Codex 原实现采用同样的 largest
JSON 选择规则；Schema 合法也不是记忆事实正确性的证明。

## 发布

作为 1.0.5 补丁，保留现有 Release 和用户数据。数据库、文件布局、
配置、reader/hook/notes、引用语义和正式基线样例均不变。已有成功
来源不重提取，旧失败任务沿用版本更新后重新提供一次预算的机制。
