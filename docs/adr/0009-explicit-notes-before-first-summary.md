# ADR 0009：首份摘要之前提供最小的 notes 入口

状态：接受。来源：用户授权修复首次明确记忆请求缺少指引的小问题；
要求核对模型角色、避免重复和过度设计，仅提交代码，不发布版本。

## 决策

仍使用唯一的 UserPromptSubmit 注入路径，不恢复插件 System Prompt。
当前上下文首次检查时：有可用摘要则沿用完整 read_path_v2；没有可用
摘要则只注入 notes_only.md，说明用户明确要求记住/忘记/纠正时在稳定
notes 目录新增 Markdown，后续由合并应用。不提供空摘要、检索/引用
规则、CLI 教程或额外工具。关闭 reader 或已经检查过则不输出。

短模板是对无摘要情形的替代，不是追加；完整 prompt 不变。两种结果
都完成当前上下文检查，后续首次发布不会突然补入完整摘要。普通 resume
不重复，compact 后在下一个已有入口重新检查。无需新配置、数据库表、
状态版本或已有 receipt 迁移。已开始的会话不会因更新强行补入规则。

读取故障同样可以退到只说明 notes 写入，不猜测或恢复损坏的摘要。
短指引只需要已知的本地 notes 路径，不依赖生成配置、SQLite、认证或
网络。目录由实际写文件工具按需创建，reader 不伪造正式记忆产物。

## 与 Codex 的关系与层级取舍

Codex v2 无摘要时不贡献完整阅读片段；开启 dedicated_tools 后，
add_ad_hoc_note 的注册只检查 enabled/dedicated_tools，不要求摘要
存在。我们不引入一套专用 Tool 服务，而用短指引和现有 Write 表达
同一个显式请求入口。这不声称与上游默认无摘要行为完全相同。

Kimi 静态 Plugin System Prompt 在默认模板自动加载，不需要点名；
但自定义 SYSTEM.md 可以不包含它。模型请求里静态文本是 Chat 的
system、Responses 的 instructions 或 Anthropic 的 system；成功
hook 内容仍是 user 消息，不是工具输出。较高优先级并不能解决静态
内容被自定义模板省略的问题；这个小补丁不需要额外双通道或角色改写。

## 验证和发布

三种协议都通过真实 Kimi + 本地脚本模型检查角色、去重和自定义模板；
另以真实 Write 工具验证首次明确请求保存 note。测试不使用真实会话、
凭据或付费模型，也不声称脚本验证等同于实际模型行为质量保证。

不替换现有 ZIP。代码和未发布变更记录提交到主分支，等待后续正式版本。
