# ADR 0014：独立版本、明确下限、统一源码基线

状态：接受。来源：用户授权在逐版本绑定与跨版本兼容之间决策，并假设
维护 agent 会定期检查上游、按需提交和发布。

## 不采用 Kimi 与插件一一同号发布

正常小版本通常不破坏实际契约，而原生插件更新需要用户确认；逐版本
绑定会制造 Kimi 已更新但插件尚未发布/尚未安装的空档。版本号相等也
不能证明字段语义或高级模型选项完全相同，因此保持插件自己的 semver。

1.1.0 的最低支持版本为 Kimi 2.1.0，当前完整平台测试和两类 vendored
源码统一到官方 2.1.1 发布 commit。更新 OAuth 基线之前逐文件验证，
确认原文件与新 commit 一致，而不是伪造其来源。两个版本值不是混用
实现：最低版本是兼容保证下限，2.1.1 是实际固定实现/测试基线。

新产品版本继续尝试当前契约，只对明确低于下限给出可操作诊断。未知
关键历史语义不猜测，不把读取失败视为空历史。未来确需不兼容接口时，
增加针对真实差异的薄适配；不预建 N 个几乎相同的 HostAdapter 类。
发生重大宿主架构变更且维护旧行为不合理时，可在插件 major 提高下限，
但仍应保留用户数据与明确迁移/升级说明。

## 发布与维护

六平台 CI 使用统一 pinned host；最低 host 在额外 Linux 作真实契约
测试，参与发布门禁。每周和手动 workflow 检查最新稳定版及相关源码
变化，跑实际安装/请求/续聊/多 hook 阻断等回归，不调用付费模型，
不自动提交补丁或发 Release。报告供维护 agent 判断是否需要修改。

发现实际破坏性变化后，维护 agent 最小修改历史/config/认证/requester
边界，统一更新 pin/来源 hash/支持表，并重新验证最低与当前版本。
所有发布保持不可覆盖；插件更新通过原生 Marketplace，不自动升级
用户的 Kimi。后台不兼容时提供状态/doctor 中的更新提示，不把它加入
模型 prompt，也不阻止旧记忆读取。
