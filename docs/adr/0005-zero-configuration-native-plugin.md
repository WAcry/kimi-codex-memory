# ADR 0005：零配置、Windows、原生插件与契约驱动升级

状态：接受。来源：用户对零配置、原生插件和跨平台发布的明确实施要求。

## 决策

项目名为 kimi-codex-memory，采用 Kimi 原生 Plugin/Marketplace 安装。用户
已经安装 Kimi，不需要先安装 Python、uv、Node 或第二份 Kimi。PyPI 不是用户
分发渠道。可以使用必要的自动构建与 ZIP 发布，但不把构建工具变成用户依赖。

Windows 是正式目标，与 macOS/Linux 一样需要平台测试。保留 Python 核心；
不得仅为语言与 Codex 相同而重写 Rust。Codex 原版 prompts 原样保存在
vendor/codex；实际模板的最小改动按 ADR 0008 直接写入，不再追加一套
宿主解释或通过替换自然语言来改指令。

不额外配置时，提取与合并使用 Kimi 当前默认模型及其认证：包括 Kimi 订阅
和第三方 provider。支持 OpenAI Chat Completions、Anthropic Messages、
OpenAI Responses；不支持 Gemini，也不增加旧会话协议分支。

模型预算使用有效配置窗口，而不是服务商宣传的理论最大窗口。用户将 1M
模型设成 400K 时必须尊重 400K。未知窗口回退 256,000 tokens；以 70% 为
提取预算依据，同时保留请求开销和输出空间。其余默认尽量沿用 Codex。

不存在每轮或每次合并后重新注入的产品选项，也不接受这些开发期配置。
生命周期以 ADR 0006 的源码核对结果为准：首次完整上下文
和 compact 重建时注入；不因首份记忆出现或普通 resume 额外注入。

新 Kimi 版本应尝试当前接口；产品版本不同本身不是停止工作的理由。只有
实际契约不兼容或运行失败时暂停相关生成。不得自动升级、降级、重装 Kimi。
利用原生 Marketplace 提供用户可控的插件更新；不能在会话 hook 中原地
覆盖运行程序或下载/执行未经检查的更新代码。

额度/认证/网络错误可以静默失败，保留待处理工作并有限退避。不得影响已有
记忆的读取、提示词、注入或 rg/Read。不要为这些普通故障增加交互阻断。

原始会话的工具结果已包含 agent 真正读取到的证据。提取不递归追索 spill
文件、不会为了追求完整日志而重新运行工具，也不额外保存完整聊天历史。

## 升级责任

以 ADR 0007 中的 1.0.0 为用户兼容起点。只支持当前 Kimi 契约，不等于
可以丢弃正式用户的记忆和数据库。升级保留数据，必要迁移必须可恢复。
配置文件只存用户覆盖，不能把某次发行
的全部默认值或测试版本永久锁进用户配置。
