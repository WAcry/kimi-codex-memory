# ADR 0006：按 Codex 上下文边界注入，升级采用自然交接

状态：接受。来源：用户要求对照 memory v2 源码决定是否恢复注入，并授权
直接实现；普通可恢复故障不扩展为复杂的进程升级管理。

本记录替代 ADR 0005 中“首次记忆出现就注入、普通 resume 总是重新注入”
的说法。那两项是先前实现的额外行为，不是已经证实的 Codex 机制。

## 上下文

Codex v2 在构建完整初始上下文时贡献 memory fragment。没有摘要也完成
该上下文边界，后台首次生成不主动推送。普通续用/恢复保留已有上下文与
reference baseline，不额外注入当前最新摘要。

Codex compact 会重建初始上下文：手动/turn 前压缩延至正常 turn，turn
中压缩则直接放进 replacement history。因此保留 Kimi PostCompact 的
下一可用入口补入；不添加绕过宿主的即时插入 API，也不声称时间点完全相同。

新会话首次有效输入时检查一次，即使此时没有摘要也不在后续普通 turn
轮询补入。仅当真的发生 compaction 重建，才重新检查当前摘要。因此首份
记忆也可能在随后的真实 compact 后首次进入该会话，但不是由“生成完成”
这个事件触发。正常 resume 不清除本地已检查标记。

按 ADR 0008，阅读规则与摘要由一个自包含 hook 消息提供，不另加静态
插件系统规则；注入和本地文件查阅继续与后台健康状态分离。无需读取原始
session/联网来判断是否已经注入，不添加额外的产品开关。

## 宿主升级

可用旧 helper 可以完成当前批次，不因磁盘安装版本变化而热重启。自有
helper 读取后结束，下次自然解析用户当前安装；用户服务只借用、绝不关闭。
移除事先运行 kimi --version 以及启动前后版本相等判断。新版本以实际
API 契约为准；升级中的短暂失败保留队列、静默重试，不回滚 Kimi。

保留且仅对子进程设置 KIMI_CODE_NO_AUTO_UPDATE=1。它防止由后台调用触发
自动更新，不阻止用户升级；Kimi 的显式手动 staged update 可能仍被原生
代码执行，不干预该用户决定。不能把该变量描述成完整的“冻结版本”。

hook launcher 在启动 Kimi 前就设置该变量；不修改父进程、配置文件或
全局环境。清理只涉及实际由我们启动的进程树，避免 native re-exec 的
等待父进程退出后留一个孤儿 helper。不添加常驻监督器、文件监控和复杂
的跨版本并存协议。
