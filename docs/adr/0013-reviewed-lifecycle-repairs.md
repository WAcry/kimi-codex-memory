# ADR 0013：修复状态生命周期，不扩张记忆功能

状态：接受。来源：用户要求复核第三方报告，修复与 Codex 基线及实际
宿主行为有关的缺陷，避免为可恢复的罕见情况引入庞大的新系统。

## 决策

保留两阶段生成、SQLite、受限合并工具和不可变快照。修复以下具体缺陷：

- 发布前删临时 diff/.git，不让删除内容通过最新快照的处理材料继续暴露。
  prepare 已会从实际文件建立基线，无需公开旧 Git 历史。已有版本的当前
  快照也会在下次 worker 启动时清理这两个处理产物，无模型调用。
- 注入分 prepared/committed。经过源码和真实 Kimi 多-hook 实验确认，
  匹配的用户 TurnStarted 位于 UserPromptSubmit gate 接受及内容追加
  之后；只有匹配 prompt hash 才标记接纳。不是正式持久化 ack，也不
  声称 exactly-once；丢失确认时选择可能重发，而不是永久漏掉记忆。
- 同一次渲染返回 text/generation/summary_hash，读取和 pin 登记与
  指针发布/GC 使用短锁。GC 锁内只改名，递归删除在锁外完成。
- 活动续期 pin，不重复注入；默认 30 天无活动后可以释放快照。恢复时
  已不存在则在下一个输入受控重建，不无限保留所有生成版本。
- 外部预算、限流、认证/配置、网络故障延后，不烧掉来源的有限失败次数。
  输出/来源契约错误仍有限重试。有效模型/请求器指纹变化重新允许失败
  项；显式 retry/list 命令提供无模型消耗的恢复，不要求手工编辑数据库。
- hook shell 直接启动发布包 executable，不再经过 Kimi 的内部 Node
  命令；生成桥接仍可失败并等待插件更新，不把其依赖扩散到纯本地读取。

## 刻意不做

不做跨宿主持久化消息总线、不扫描原始日志查投递、不锁住模型/网络调用，
不为任意同名重复 prompt/进程崩溃保证 exactly-once。不做永久 pin、不
新增全盘秘密擦除服务，不把删除会话、forget note 和彻底擦除混为一谈。
不增加向量检索或改变 Codex memory-v2 的内容、排名及生命周期规则。

这些改动分别修复外置快照/钩子/多-provider 边界，不是新的记忆推理功能。
现有 schema=1 与公开 1.0.0 数据保留，旧 checked receipt 继续按已交付
解释；无法事后确认旧版本漏投递，可用新会话或 compact 恢复。普通
恢复仍不重复注入，只有缺失快照或未确认投递会重试。
